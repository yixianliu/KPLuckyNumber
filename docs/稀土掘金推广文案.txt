## 为什么要重造这个轮子？

### 现状痛点调研
| 场景 | 传统做法 | 痛点 |
|------|----------|------|
| 拿数据 | 打开 3 个网站 → 复制粘贴 Excel → 手工去重 | 耗时、易错、无增量 |
| 跑算法 | 网上�个脚本 → 改改参数 → 跑一遍 | 单算法、口径不一、不可复现、无横向对比 |
| 验证效果 | 眼球观察「好像准」 | 无自动验证、无命中率统计、无长期复盘 |
| AI 解读 | 直接喂 Prompt → 拿到乱码 JSON | 格式不稳定、解析失败、推理链丢失、无法入库 |
| 部署跑通 | pip install 一堆 → 缺 Redis 就崩 | 环境脆弱、强依赖、新手跑不起来 |

### 我们的答案
**不造「预测神器」，造「数据分析基建」。**  
把上述五个痛点，分别映射为五个工程化模块，**同一份输入、同一套框架、可复现、可追溯、可回滚**。

## 核心架构：六阶段流水线 + 两大引擎

### 1️⃣ 智能分析中心（一键触发的六阶段流水线）
```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│ 统计预测    │→  │ 走势研判    │→  │ 快速预测    │→  │ 命中率优化  │→  │ 在线学习    │→  │ AI辅助解读  │
│ (七算法融合)│   │ (40期周期)  │   │ (Top-N出号) │   │ (自动验证)  │   │ (逐算法归因)│   │ (JSON修复)  │
└─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘   └─────────────┘
      │               │               │               │               │               │
      ▼               ▼               ▼               ▼               ▼               ▼
  predictor.py   trend_analyzer  predictor.py   online_learner  online_learner   json_repair +
  (核心融合)     (趋势引擎)      (最终入库)     (验证闭环)      (per-algo归因)    AI报告入库
```
- **全后台线程执行**（`task_manager.py` 单工作者队列），GUI 主线程零阻塞
- **两步简化流水线**（v3.15+）：原 step1 专家文章/step2 走势报告/step3 综合报告已注释停用，现仅保留 `_calc_statistical_prediction` + `step4_final_prediction`

### 2️⃣ 自我进化引擎（后台守护线程，`self_evolution.py`）
```
数据量达阈值 → 触发重训 → walk-forward样本外评估 → 超越历史基线? → 是: 更新线上权重 / 否: 归档为试验
```
- **六阶段**：数据准备 → 特征工程 → 模型训练 → 无偏评估 → 版本对比 → 线上切换/归档
- **进化版本全入库**（`p5_evolution_version`），过程可观测、可回滚
- **深度调优器**（`evolution_tuner.py`）：组件缓存 + 坐标下降搜索，避免重复计算

## 五大痛点的工程化解法

### 痛点 1：数据源分散 → 多源爬虫 + 自动入库（`data_fetcher.py`）
```python
# 核心逻辑：增量抓取 + 去重 + 补全缺失期号
class P5Spider:
    def fetch_incremental(self, last_issue: str) -> List[DrawRecord]:
        # 1. 多源并发请求（官网+备用源）
        # 2. 统一字段映射 + 类型归一化
        # 3. 基于期号去重 + 缺失期号检测
        # 4. 批量入库（事务保证原子性）
```
- **关键点**：请求层解耦（易扩展新源）、增量键设计（期号唯一索引）、异常重试指数退避

### 痛点 2：算法不可比 → 统一融合框架 + 权重冻结（`predictor.py`）
```python
# 七算法融合核心：加权融合 + 权重可冻结
class AdaptiveWeightManager:
    FROZEN_WEIGHTS = {
        'frequency': 0.68, 'supervised': 0.14, 'bayesian': 0.10,
        'omission': 0.06, 'trend': 0.01, 'markov': 0.005,
        'pattern': 0.003, 'feature': 0.002
    }
    lookback = 60  # 统一回看窗口
```
- **关键点**：每算法独立输出概率分布 → 加权融合 → 权重配置外置化（可冻结/可调优），**不把核心逻辑塞进黑箱**

### 痛点 3：预测无验证 → 在线学习闭环 + 逐算法归因（`online_learner.py`）
```python
# 每期开奖后自动执行：验证命中 → 统计命中率 → 归因到各算法
def verify_and_attribute(self, prediction_uuid: str, actual_draw: List[int]):
    # 1. 读取预测记录（含 fused_probabilities / top_combinations）
    # 2. 计算 Top-1/3/5 命中
    # 3. 优先读 p5_ai_report.per_algo_predictions 做逐算法归因
    # 4. 更新命中率统计表 + 写入验证日志
```
- **关键点**：`per_algo_predictions` 独立列存储各算法原始输出，验证时可精确归因到单算法，**不混淆融合后的整体表现**

### 痛点 4：AI解读不可控 → JSON修复 + 结构化归因（`json_repair.py` + `pipeline.py`）
```python
# 修复大模型返回的脏 JSON：截断、缺括号、注释、尾逗号等
def repair_json(raw: str) -> Dict:
    # 1. 提取首个完整 JSON 对象/数组
    # 2. 容错解析：补全括号、去注释、修复尾逗号
    # 3. Schema 校验（必含字段：analysis, suggestion, confidence 等）
    # 4. 失败则回退默认模板，保证流程不中断
```
- **关键点**：**解析不抛异常、结构不丢字段、推理链入库**，AI 解读从「黑箱」变「白箱」

### 痛点 5：环境脆弱 → 惰性加载 + 优雅降级（全模块通用模式）
```python
# 模块内部导入，启动时不加载重依赖
# modules/predictor.py
def _lazy_import_sklearn(self):
    try:
        from sklearn.ensemble import GradientBoostingClassifier
        return GradientBoostingClassifier
    except ImportError:
        log.warning("sklearn 缺失，监督学习算法降级为规则启发式")
        return None

# GUI 延迟绑定重模块（main.py）
Validator = _LazyClass('modules.validator', 'Validator')
```
- **关键点**：
  - **启动快**：不 import 重依赖（matplotlib、sklearn、redis 等）
  - **缺啥降啥**：Redis 缺失 → 自动退回本地缓存（`cache.py`）；sklearn 缺失 → 监督学习降级规则启发式
  - **三向引用扫描铁律**：删除模块前必扫 `static import` / `import_module` / `_LazyClass字符串`，**杜绝运行时 ImportError**

## 五大独特价值：差异化在哪里？

### 1. 多算法融合，权重透明不藏私
| 算法 | 权重 | 说明 |
|------|------|------|
| 频率统计 | 0.68 | 基础统计权重最高，lookback=60 |
| 监督学习 | 0.14 | GradientBoosting 按位建模（需 sklearn） |
| 贝叶斯 | 0.10 | 先验+似然更新，Dirichlet 平滑 |
| 遗漏值 | 0.06 | 综合遗漏期数加权 |
| 趋势 | 0.01 | 升平降/奇偶/大小趋势 |
| 马尔可夫 | 0.005 | 状态转移矩阵 |
| 形态 | 0.003 | 顺子/对子/豹子等模式 |
| 特征工程 | 0.002 | 组合特征辅助 |

> **权重可冻结、可外置配置、可进化调优**，线上版本与调优版本严格隔离。

### 2. 全链路可追溯：5 表贯穿始终
| 表名 | 核心字段 | 用途 |
|------|----------|------|
| `p5_history_data` | issue, draw_date, n1-n5, test_n1-n5 | 原始开奖数据 |
| `p5_prediction_record` | predict_uuid, fused_probabilities, top_combinations, predict_time, risk_warning | 预测产物 |
| `p5_ai_report` | report_uuid, per_algo_predictions, ai_analysis, confidence | AI解读+逐算法归因 |
| `p5_bayesian_result` | issue, prior, posterior, alpha_params | 贝叶斯中间结果 |
| `p5_evolution_version` | version, weights, metrics, status, baseline_comparison | 进化版本管理 |

> **任意一次分析，可回溯到：原始开奖 → 算法中间概率 → 融合权重 → AI推理链 → 最终入库记录**

### 3. 诚实边界，不忽悠用户
- **系统级声明**：启动页、分析结果、导出报告均显性标注「无法稳定超越随机基线」
- **置信区间披露**：命中率报表自带 95% CI，噪声波动一目了然
- **拒绝营销话术**：代码、文档、UI 绝无「必中」「稳赚」「提高中奖率」等表述

### 4. 自我进化：自动重训 + 无偏评估
```python
# walk-forward 评估伪代码（evolution_tuner.py）
def walk_forward_evaluate(candidate_weights, historical_data, window=200, step=50):
    scores = []
    for i in range(window, len(historical_data), step):
        train = historical_data[:i]
        test = historical_data[i:i+step]
        # 用 candidate_weights 在 train 上融合，在 test 上验证
        score = evaluate_fusion(candidate_weights, train, test)
        scores.append(score)
    return np.mean(scores), np.std(scores)  # 均值±标准差，而非单点指标
```
- **候选方案必须「均值超越历史基线 + 标准差可控」才能入线上**，否则归档为 `trial` 状态

### 5. 三级智能缓存：秒级响应（`smart_cache.py`）
| 缓存层 | 策略 | TTL | 典型场景 |
|--------|------|-----|----------|
| **L1 长期** | LFU | 90 天 | 历史开奖、算法权重、进化版本 |
| **L2 短期** | LRU | 7 天 | 最近查询的统计特征、走势数据 |
| **L3 AI响应** | LRU | 1 天 | 大模型解读结果（避免重复调用） |

- **Redis 优先，本地降级**：`redis_storage_manager.py` + `cache.py` 双通道，缺 Redis 无感切换
- **缓存键规范**：`kpluckynumber:pl5:{module}:{id}`，统一前缀、统一 TTL 管理

## 硬核技术细节：踩坑与避坑

### 💥 坑 1：模块删除导致运行时 `ImportError`
> **现象**：`grep "from modules.validator import"` 显示零引用 → 删掉 `validator.py` → 启动崩溃  
> **根因**：`main.py` 用 `_LazyClass('modules.validator', 'Validator')` 延迟绑定，**字符串引用 grep 扫不到**  
> **铁律**：删除模块前**三向扫描** —— 静态 import / 动态 `import_module` / `_LazyClass` 字符串 —— **全零才可删**  
> **工具化**：可复用 Skill `py-project-cleanup-docstrings` 内置 `scripts/scan_references.py` 自动完成三向扫描

### 💥 坑 2：`backtester.py` 顶层 `import matplotlib` 导致无依赖环境全模块不可用
> **修复**：改为函数内部懒导入，`try/except` 降级为纯文本报表模式

### 💥 坑 3：大模型返回 Markdown 代码块包裹 JSON，直接 `json.loads` 炸裂
> **修复**：`json_repair.py` 先提取 ````json ... ```` 再修复，兼容思维链输出

### 💥 坑 4：滚动回测数据泄露（Look-ahead Bias）
> **修复**：严格 `walk-forward`，训练集严格早于测试集，**绝不使用未来数据训练**

### 💥 坑 5：GUI 卡顿（主线程跑重计算）
> **修复**：`task_manager.py` 单工作者线程 + 队列，所有耗时任务（爬取/分析/重训/回测）入队，**主线程只管轮询进度刷新 UI**

## 诚实基线数据：拒绝营销号

| 指标 | 随机基线 | 系统实测 (v3.59) | 统计显著性 |
|------|----------|------------------|------------|
| **Top-1 命中率** | 10.0% | **≈ 9.9%** | p > 0.05（无显著差异） |
| **Top-3 命中率** | 30.0% | **≈ 29.8%** | p > 0.05（无显著差异） |
| **Top-5 命中率** | 50.0% | **≈ 49.6%** | p > 0.05（无显著差异） |

> **结论**：系统**无法稳定超越随机基线**，这正是「诚实边界」的体现。  
> 如果你看到某工具宣称「Top-1 命中率 20%+」，大概率是**幸存者偏差/过拟合/样本内作弊**。
